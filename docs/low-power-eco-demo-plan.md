# STM32F103 Eco 低功耗最小闭环计划

> 状态：`实施中`  
> 目标：在现有 STM32F103 + FreeRTOS 环境终端中，完成一个**可测量、可重复、可解释边界**的 Eco 模式。它不是“加入低功耗 API”的教程复刻，而是验证设备在非 OTA 空闲期能按周期采样、进入 STOP、由 RTC 唤醒并恢复关键功能的完整工程闭环。

## 1. 本次范围与非目标

### 完成后的可声明事实

- 在固定硬件和供电条件下，记录 Normal 与 Eco 的电流或周期能量。
- Eco 模式会关闭明确列出的非必要负载，STM32 在非 OTA 空闲窗口进入 STOP。
- RTC 周期唤醒后，系统时钟、必要外设和应用任务恢复；串口命令与传感器快照可用。
- 连续完成至少 100 次睡眠—唤醒循环，记录成功数、失败数和复位原因。
- OTA 活跃时禁止进入 Eco，升级主链路回归通过。

### 明确不做

- 不宣称 A/B 分区、掉电自动回滚或“超低功耗”指标。
- 不在第一版同时重构 UI、ESP32 固件、任务架构或增加新传感器。
- 不把 `configUSE_TICKLESS_IDLE=1` 当作第一步；当前项目尚未实现其时基补偿与 FreeRTOS 集成验证。
- 不在没有测量数据时把 STOP 写进简历成果。

## 2. 现有约束（实现前必须保持准确）

| 约束 | 当前事实 | 对设计的影响 |
|---|---|---|
| MCU / RTOS | STM32F103C8T6、FreeRTOS，`configUSE_TICKLESS_IDLE=0` | 第一版由应用明确管理 Eco 状态，不能假称内核自动省电。 |
| 看门狗 | IWDG 约 4 秒，LSI 驱动 | 首版 RTC 睡眠窗口必须显著短于实测最短 watchdog 超时，且先做实际验证；不能直接睡 10 秒。 |
| 正常负载 | ESP32、OLED、TFT、WS2812B、I2C 传感器、继电器/蜂鸣器等 | 要区分“整机输入功耗”与“MCU/子系统功耗”；先测谁是大头再下结论。 |
| OTA | 单 Application 分区；ESP32 与 STM32 经 UART 协作 | OTA 开始到结束期间保持 Normal；不能为省电中断 UART 升级链路。 |
| RAM | 20 KB SRAM，现有应用余量有限 | 不新增大缓冲或新任务；优先复用现有状态与任务。 |

## 3. 验收工况和测量边界（先定，再写代码）

### 3.1 固定两种对比工况

| 项目 | Normal 基线 | Eco |
|---|---|---|
| STM32 | 正常时钟、现有任务正常运行 | 周期采样结束后准备 STOP，RTC 唤醒 |
| ESP32 | 固定为同一种状态（例如 Wi-Fi/蓝牙都关闭，或两者均开启） | 必须与 Normal 完全一致 |
| 显示、灯带、继电器、蜂鸣器 | 固定开关状态并记录 | 显式关闭/维持的项目逐项记录 |
| 传感器 | 固定连接、固定采样周期 | 记录哪些器件进入休眠、哪些持续供电 |
| OTA | 不进行 OTA | 不进行 OTA；另做一次 Eco 退出后 OTA 回归 |

不要在一组数据里混用不同 Wi-Fi 状态、屏幕亮度或 USB 供电。否则数据不能比较。

### 3.2 两层测量结论

1. **整机边界（必做）**：在整个终端的外部稳定电源输入处测量。它回答“用户真正用到的设备是否省电”。
2. **STM32/子系统边界（条件做）**：只有在能安全隔离 ESP32、显示和执行器供电时才测。它回答“MCU STOP 本身贡献多少”。不能隔离就明确不下 MCU 单独功耗结论。

## 4. 电流测量：今天就能开始的安全做法

### 可用仪器的优先级

1. **台式电源带 mA 显示 / 电流记录**：最方便测整机稳态平均电流；先确认低电流量程的分辨率。
2. **万用表 DC mA 档串联**：足够做 Normal/Eco 的稳态平均值对比，但看不到毫秒级唤醒峰值。
3. **示波器 + 分流电阻**：用于观察唤醒瞬态。先从 `1 Ω`、足够功率的串联分流开始，测其两端压降，按 `I = V / R` 换算；仅在确认最大电流和供电压降可接受后使用。

USB 电流表只能作为整机粗略参考；若量程/分辨率不足，不能用它证明 STOP 的微小改善。

### 万用表串联步骤（整机基线）

1. **先完全断电。** 确认终端只有一个供电来源。
2. 将万用表黑表笔接 `COM`，红表笔先接高电流插孔并选择最高 DC 电流量程。
3. 把表**串在外部电源正极与终端 VCC 之间**：`电源 + → 万用表 A/mA → 终端 VCC`。负极/GND 保持直接相连。
4. 上电确认无异常，再逐级切换到 mA 量程以提高分辨率；切换量程前先断电，避免烧表内保险丝。
5. 每个工况等待状态稳定后，记录至少 60 秒读数；Eco 需覆盖多个睡眠/唤醒周期。

**绝不能**把电流档万用表并联在 VCC 和 GND 上；那相当于近似短路。

### ST-Link 连接注意事项

- ST-Link 只接 `SWDIO`、`SWCLK`、`GND`（需要复位调试时再接 `NRST`）；**不要接 ST-Link 的 3.3V/5V 供电脚**，否则会绕过或污染电流测量边界。
- 让被测外部电源单独给板子供电；ST-Link 的目标电压脚如仅作参考电压，按调试器实际接线确认，不把它当供电线。
- STOP 测量时不要持续单步、halt CPU 或打开会周期访问目标的调试轮询；这些操作会改变功耗和唤醒行为。需要抓日志时，让固件把结果在唤醒后通过 UART 输出。

## 5. 里程碑与产物

### M0：测量基线（先完成）

- [ ] 画出实际供电路径：外部电源、Blue Pill、ESP32、显示、传感器与执行器各由谁供电。
- [ ] 选定整机测量点，记录仪器型号、量程、供电电压和接线照片。
- [ ] 在固定 Normal 工况下完成至少 3 次 60 秒测量。
- [ ] 记录屏幕、灯带、ESP32 状态，确认哪类负载主导电流。

**进入 M1 的条件：**有一行可信的 Normal 基线数据；没有它不改低功耗代码。

### M1：最小 STOP 探针（先脱离完整 RTOS 集成）

- [ ] 新增一个独立、可烧录的 F103 低功耗探针目标：RTC 定时唤醒 → STOP → 唤醒后恢复时钟 → UART 输出递增唤醒计数。
- [ ] 显式记录睡眠请求时长、实际唤醒间隔和复位标志。
- [ ] 在接入 IWDG 的条件下验证至少 100 次循环不被非预期复位；若 watchdog 限制无法满足，先调整设计，不掩盖问题。
- [ ] 记录 STOP 前后 SysTick、UART、时钟恢复的真实行为。

**进入 M2 的条件：**探针 100 次通过，且有串口日志/照片证明。探针失败不将 Stop 代码混入主应用。

### M2：主应用 Eco 状态机

- [ ] 定义最小状态：`NORMAL`、`ECO_PREPARE`、`ECO_SLEEP`、`ECO_RESUME`，以及一次可观测的状态/计数。
- [ ] 仅在无 OTA、无用户交互、无执行器危险状态时允许 `ECO_PREPARE`。
- [ ] 停止或降载可关闭的显示/灯带/周期轮询；每一项都要有恢复路径。
- [ ] 进入 STOP 前完成 UART 空闲与任务协作；唤醒后恢复时钟、必要外设和应用时间基准。
- [ ] 保持 OTA 活跃期间强制 Normal，并跑一次完整 OTA 回归。

**第一版睡眠窗口建议：**从明显短于约 4 秒 IWDG 标称超时的窗口开始，以实测为准；不预设节省百分比。

### M3：测量与回归

- [ ] 在 M0 的同一边界和工况，重复至少 3 次 Eco 测量。
- [ ] 做 100 次睡眠/唤醒循环，输出成功、失败和 reset cause。
- [ ] 做一次正常 UART 命令、传感器快照、显示恢复和 OTA 回归。
- [ ] 在本文件或独立报告中写清结果、失败、限制和下一步，不只保留“成功”截图。
